Line-Following Maze Robot

A wheeled robot that follows a taped line through a maze, handles the junctions, and reaches the end on its own. The control program is written in assembly.

Role
Assembly programming, sensor calibration, testing on the course
Stack
Assembly language, microcontroller robot platform, reflective line sensors, LCD readout

The robot running the maze from the start marker to the end.

The task

The course is a maze of black tape on a white board with a marked start and finish. The robot reads the line with a row of reflective sensors underneath, steers to keep the line centred, and has to recognise junctions and dead ends rather than just wander. A small LCD on top shows the sensor state and what the program thinks it is doing, which was the main debugging tool.

SensingReflective line sensors read through the microcontroller's ADC
ControlSteering from sensor readings, with states for straight, turning, and junction handling
FeedbackLCD readout of sensor values and current state while running
ResultCompletes the maze from start to finish, shown in the video above

Writing it in assembly

There is no compiler doing the housekeeping here. Reading a sensor means setting up the ADC, waiting for the conversion, and pulling the result out of a register. The main loop is a state machine written as branches and jumps, with subroutines for the motor commands and the display. Getting the timing right, especially how long to hold a turn before checking the sensors again, took the most iteration on the actual course.

It was also a good lesson in how much a high-level language hides. After this, reading a datasheet register map and knowing exactly what the hardware is doing on each instruction felt a lot less abstract.
